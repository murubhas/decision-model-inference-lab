# EKS Jev Guardrail Pilot - 2026-09-29

> Historical whole-battery Jev-first baseline. Its check-specific routing
> recommendation was subsequently implemented and measured in
> [`eks-check-specific-hybrid-2026-09-29.md`](eks-check-specific-hybrid-2026-09-29.md).

## Decision Summary

This pilot provides measured evidence that a typed decision model can be used
as an inference optimization for repeated semantic guardrails. It does **not**
yet prove production safety: all 34 corpus labels are draft, there was one
measured repetition, and two LLM response-contract failures remain part of the
result.

The current recommendation is boundary-specific:

- Use Jev directly for bounded, low-ambiguity checks such as tool-intent and
  tool-argument safety after approved-label validation.
- Use hybrid routing for input scope and adversarial-text ambiguity.
- Do not use Jev alone for nuanced final-output relevance or grounding with the
  present questions and thresholds. Route those checks to the LLM or redesign
  the decision criteria and validate again.
- Keep generation, evidence synthesis, explanation, and tool planning on the
  generative model. Jev is the semantic decision plane, not the agent model.

## Where Jev Won

On the draft corpus, both Jev and LLM achieved 100% per-question accuracy for:

- tool intent alignment;
- tool argument safety;
- prompt-injection detection;
- sensitive-data exposure; and
- policy leakage.

The tool-call checks are the strongest direct-Jev candidate: Jev matched the LLM
on the tested labels while removing all generative calls and most latency and
cost. Jev also remained available on the harmful input for which generated LLM
output violated the strict JSON contract.

## Where Jev Did Not Win

Jev was materially weaker on positive, nuanced judgments:

| Check | LLM recall | Jev recall |
| --- | ---: | ---: |
| Input is in scope | 75.00% | 62.50% |
| Output is grounded | 71.43% | 57.14% |
| Output is relevant | 72.73% | 36.36% |

The direct Jev path incorrectly blocked safe abstention/placeholder responses
and escalated ambiguous but valid inputs. It also changed one expected block to
an escalation, producing the 5.56% unsafe-miss rate. Hybrid removed that unsafe
miss but still inherited two Jev-clear false blocks. This means the current
all-question fallback rule is insufficient: a confidently wrong Jev decision
does not trigger an LLM.

The next design should route by check, not only by aggregate uncertainty:

- keep tool safety, prompt injection, sensitive exposure, and policy leakage on
  Jev when confidence is clear;
- route input scope, output relevance, and output grounding to the LLM until
  their criteria and calibration improve; and
- retain deterministic checks for schema, known-secret patterns, tool
  allowlists, evidence existence, and destructive-action policy.

## Cost Evidence

The versioned catalog used public list prices checked on 2026-09-28:

- Bedrock global Claude Sonnet 5.5: $2.00/M input and $10.00/M output tokens.
- Jev: $42/B input tokens, or $0.042/M.

TypeSafe's public page did not state a Jev output-token price. The report treats
Jev output as unbilled and requires invoice reconciliation; this is an explicit
assumption, not a zero-price claim.

For the corpus, successful decisions cost an estimated $0.088512 on LLM,
$0.000799512 on Jev, and $0.030909562 on hybrid. The hybrid break-even estimate
was a 99.12% fallback rate under this corpus's observed token mix. Its actual
successful fallback rate was 33.33%, yielding 65.08% guardrail savings.

At the same corpus token mix, one million semantic decisions project to about
`$2,682.18` on LLM, `$936.65` on hybrid, and `$23.52` on Jev before discounts or
unpriced Jev output. That is a projected hybrid saving of `$1,745.53` per
million decisions. An agent averaging five such checks per turn would project
to `$8,727.64` saved per million turns. This is a linear scenario calculation,
not a traffic forecast; real savings move with payload size and fallback rate.

### Live A2A Business Request

The same p5 versus p5e request ran end to end in `SHADOW` enforcement under all
three paths. Every run invoked Sonnet for recommendation generation and three
MCP tool calls; only the five semantic guardrail boundaries changed.

| Metric | LLM | Jev | Hybrid |
| --- | ---: | ---: | ---: |
| End-to-end duration | 35.82 s | 30.49 s | 36.98 s |
| Guardrail provider time | 6.346 s | 0.905 s | 4.731 s |
| Guardrail cost | $0.049824 | $0.000598 | $0.045286 |
| Primary generation cost | $0.086000 | $0.086114 | $0.085498 |
| Total provider cost | $0.135824 | $0.086712 | $0.130784 |
| Guardrail savings vs LLM | n/a | 98.80% | 9.11% |
| Overall provider savings vs LLM | n/a | 36.16% | 3.71% |

The pure-Jev total is a `SHADOW`-mode cost floor, not a production operating
cost: Jev returned `ESCALATE` on three of the five live boundaries. A production
system must price and implement those LLM or human continuations, as the hybrid
path does. Shadow mode also allowed all three runs to finish regardless of the
selected semantic action.

Pure Jev reduced measured guardrail provider time by 85.74%. Hybrid reduced it
by 25.46%, but its 60% fallback rate and very large final-output state caused
the Jev-first request plus the fallback LLM request to duplicate input work.
That is why hybrid saved only 3.71% overall on this request despite its much
larger 65.08% corpus saving.

This is the practical inference-optimization result: moving bounded decisions
off the generative model lowered total provider cost even though primary answer
generation stayed on Sonnet. The size of the win depends on fallback rate,
boundary payload size, and whether Jev quality is acceptable for that check.

## Infrastructure Cost

The existing inference-system node group temporarily moved from one to two
on-demand `m7i.xlarge` nodes. The overlap ran from `04:37:05Z` to `05:25:55Z`,
2,930 billed seconds. At the checked Ohio public rate of $0.2016/hour, temporary
compute cost was approximately **$0.16408**. The group is restored to
`min=1`, `max=1`, `desired=1`; the benchmark Job, reader Pod, and PVC were
deleted after archival.

This one-time experiment capacity is separate from per-decision inference cost.
CodeBuild, the short-lived 1 GiB PVC, failed diagnostic calls, taxes, discounts,
and network transfer are excluded. Provider totals are estimates, not invoice
reconciliation.

## Decision

The pilot supports Jev as an inference optimization, but not as a universal LLM
replacement:

1. **Proceed with a boundary-specific hybrid design.** Direct Jev for validated
   tool and narrow risk checks; LLM for nuanced scope and answer-quality checks.
2. **Do not enable enforcement yet.** Keep `SHADOW` until labels are independently
   approved, the corpus is expanded, and multiple repetitions establish
   confidence intervals and contract-failure rates.
3. **Optimize large fallback payloads.** Avoid sending a full output/evidence
   state to both providers when the check is known to require the LLM.
4. **Reconcile billing.** Compare the catalog estimates with Bedrock CUR and the
   TypeSafe invoice before presenting production savings as audited cost.
